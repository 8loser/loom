# Test-Driven Development

TDD is the red → green loop. Tests verify behavior through
public interfaces, not implementation details.

A seam is the public boundary you test at. Tests live at
seams, never against internals. The seams for this work are
already agreed in the parent issue's Testing Decisions below — work
at those, do not introduce new ones.

Work in vertical slices: one test → one implementation →
repeat, each test a tracer bullet.
